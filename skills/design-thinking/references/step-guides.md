# Design Thinking - Step-by-Step Facilitation Guide

Full facilitation scripts for each step. For each step: state the goal, give
the instructions, offer the hints if the user is stuck, produce the Clear
Output, share the Impact/Takeaway, then wait.

---

## STEP 0: Context Setting (Warm-up)

**Ask the user:**

> "What problem are you trying to solve, or in what domain do you want to
> create a solution? (e.g., designing an expense-tracking app, improving team
> workflow, reorganizing your living space...)"

**If they are unsure:** Suggest 3 popular topics to choose from, for example:

1. A personal finance or habit-tracking app.
2. Improving a team's meeting or workflow efficiency.
3. Redesigning a living or workspace for better focus.

Receive the choice, confirm it back to them, then proceed to Step 1.

---

## STEP 1: Empathize (Understanding the User)

**Goal:** Deeply understand the target audience's pain points and needs.

**Instructions:** Ask the user to describe their target audience.

**Hint (if the user doesn't know how to start):** Ask them to answer these
3 questions:

1. **Who is your user?** (Age, profession, habits.)
2. **What is their biggest struggle or frustration** regarding this problem?
3. **If they had a magic wand,** how would they want this situation to work?

**Output:** A **User Persona** and a **List of Pain Points**. Use
`assets/user-persona-template.md`.

**Impact / Takeaway:** Helps the user realize:

> "We are solving a problem for the USER, not for ourselves. All personal
> assumptions must be set aside."

---

## STEP 2: Define (Framing the Core Problem)

**Goal:** Shift from scattered issues to a single, focused challenge.

**Instructions:** Guide the user to write a **"How Might We..." (HMW)**
statement.

**Hint:** Combine the insights from Step 1 into this structure:

> "How might we help **[User]** solve **[Pain Point]** so they can achieve
> **[Desire]**?"

*See `references/frameworks.md` for the HMW formula and examples.*

**Output:** A sharp, focused **Core Problem Statement**. Use
`assets/hmw-statement-template.md`.

**Impact / Takeaway:** Helps the user understand:

> "Defining the right problem is solving 50% of the puzzle. The HMW framework
> opens up creative space instead of leaving you stuck."

---

## STEP 3: Ideate (Generating Solutions)

**Goal:** Generate as many solutions as possible without judgment.

**Instructions:** Ask the user to list at least **3-5 ideas**, ranging from
practical to absolutely crazy.

**Hint (if they run out of ideas):** Use the **SCAMPER** method (provide
examples). See `references/frameworks.md` for the full SCAMPER list.

- **S (Substitute):** Can a step/material be replaced by something else?
- **C (Combine):** Can this idea be merged with another feature?
- **M (Modify):** What happens if we make it huge, tiny, or extremely simple?

**Output:** **Top 3** most feasible and breakthrough ideas (selected through
discussion between the AI and the user).

**Impact / Takeaway:** Helps the user realize:

> "Quantity breeds quality. The best ideas often stem from initially absurd
> thoughts."

---

## STEP 4: Prototype (Building to Learn)

**Goal:** Turn ideas into tangible forms with minimal time and cost.

**Instructions:** Guide the user on how to create a rapid, low-fidelity
prototype.

**Hint:** A prototype doesn't have to be a real product. It can be:

- A hand-drawn sketch (**Storyboard**).
- A **roleplay script** acting out the scenario.
- A simple **Excel spreadsheet**.

Ask them to choose **1 format** and describe the flow of that solution in
**3-4 steps**.

**Output:** A rough draft describing how the solution works in reality.

**Impact / Takeaway:** Helps the user grasp the rule:

> "Fail fast, learn fast. Don't build a full car when the user only needs a
> skateboard to commute."

---

## STEP 5: Test (Gathering Feedback)

**Goal:** Validate the prototype against reality to refine it.

**Instructions:** Build a feedback evaluation framework.

**Hint:** Ask the user to take their prototype (the description from Step 4)
to a friend/colleague, ask for feedback, and categorize it using this matrix:

- **I like** (What works well?)
- **I wish** (What is missing or could be better?)
- **What if** (What happens if we change part X?)

*See `references/frameworks.md` for the Feedback Matrix and
`assets/feedback-matrix-template.md` for the output template.*

**Output:** A **Feedback Matrix** and a **Next Action Decision** (Return to
Step 3, tweak Step 4, or proceed to implementation).

**Impact / Takeaway:** Helps the user deeply understand:

> "Design is a continuous loop. Feedback is not criticism; it is the raw
> material needed to design a perfect product."
