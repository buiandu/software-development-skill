# Design Thinking - Supporting Frameworks

Quick reference for the frameworks used across the 5 steps: the HMW
statement formula, the SCAMPER ideation method, the Feedback Matrix, and the
User Persona field list.

---

## 1. "How Might We..." (HMW) Formula (Step 2 - Define)

The HMW statement reframes a problem into an opportunity. It is phrased as an
open question so it invites many possible solutions instead of one fixed
answer.

**Structure:**

> "How might we help **[User]** solve **[Pain Point]** so they can achieve
> **[Desire]**?"

**Tips for a good HMW:**

- **Not too broad:** "How might we improve the world?" gives no direction.
- **Not too narrow:** "How might we add a red button?" pre-solves the idea.
- **Just right:** Broad enough for many ideas, narrow enough to stay focused.

**Examples:**

| Weak | Better |
|------|--------|
| How might we fix money problems? | How might we help freelance designers track expenses effortlessly so they can stop stressing about taxes? |
| How might we build an app? | How might we help new parents remember medication schedules so they can feel confident at night? |

## 2. SCAMPER Ideation Method (Step 3 - Ideate)

Use SCAMPER to spark new ideas when the user runs out. Walk through each
letter and ask the matching question against the current idea.

| Letter | Meaning | Prompt Question |
|--------|---------|-----------------|
| **S** | Substitute | Can a step/material/person be replaced by something else? |
| **C** | Combine | Can this idea be merged with another feature or service? |
| **A** | Adapt | What else works like this that we can borrow from? |
| **M** | Modify | What happens if we make it huge, tiny, or extremely simple? |
| **P** | Put to other uses | Who else could use this, or where else could it apply? |
| **E** | Eliminate | What can we remove to make it simpler or cheaper? |
| **R** | Reverse | What if we flip the order or do the opposite? |

**Example (expense-tracking app):**

- **Substitute:** Replace manual entry with photo receipts.
- **Combine:** Merge tracking with a savings-goal game.
- **Modify:** Make it a 5-second daily check-in instead of a full app.

## 3. Feedback Matrix (Step 5 - Test)

Categorize every piece of feedback from testers into one of three buckets.

| Bucket | Question It Answers | Focus |
|--------|---------------------|-------|
| **I like** | What works well? | Strengths to keep |
| **I wish** | What is missing or could be better? | Gaps to improve |
| **What if** | What happens if we change part X? | New directions to explore |

**Next Action Decision:** After filling the matrix, choose one path:

1. **Return to Step 3 (Ideate):** Feedback reveals the idea misses the mark; generate new solutions.
2. **Tweak Step 4 (Prototype):** The idea is right but the form needs refining.
3. **Proceed to Implementation:** Feedback is strongly positive; move toward a real build.

## 4. User Persona Fields (Step 1 - Empathize)

A persona is a fictional but realistic character representing the target user.
Capture these fields from the user's answers to the Step 1 guiding questions.

- **Name & Photo placeholder:** Give the persona a memorable name.
- **Age & Profession:** Demographics.
- **Habits & Context:** Daily routines relevant to the problem.
- **Goals:** What they are trying to achieve.
- **Frustrations / Pain Points:** Their biggest struggles.
- **Magic-Wand Wish:** The ideal outcome if anything were possible.
